# S0 离线拼音资源原型

## 1. 结论与边界

本阶段验证了离线单字拼音候选资源、两档输入字库、查询接口、有界编辑状态，
并实现了不接入正式导航的横竖屏输入页与独立真机测试固件；这仍不代表正式中文输入功能
已经交付。当前原型覆盖 GB2312 一级汉字 3,755 个，生成 394 个完整
无调拼音键、3,757 个“拼音—汉字”引用，最大单键候选数为 54。生成资源的
逻辑大小为 11,552 字节；查询使用二分查找，返回指向只读 Flash 数据的视图，
不分配堆内存，也不复制候选列表。

输入字库另覆盖 95 个可打印 ASCII、20 个常用中文标点，并内置一个专用方框加叉
缺字标记。有效 UTF-8 码点若不在有界字库中，测量和绘制都解析到同一个标记，不会
静默留白，也不会临时联网或分配堆内存。

尚未实现词组联想、连续拼音切分、前缀候选、光标编辑，以及正式
业务页面和存储提交。200 字编辑状态、候选翻页、横竖屏视觉布局和同源触摸命中区
已经完成；目标板已完成横屏人工验收，竖屏固件也已启动到就绪态且未产生持续堆占用，
竖屏交互、第 12 次局刷后的完整清理刷新以及缺字显示也已通过人工验收。仍待长时间
残影验证，因此 S0-06 继续保持未完成。排序 v2 的真机真实词汇验证已通过。本独立
测试页没有持久化语义；用户数据的掉电提交与恢复属于 S1 存储服务及后续业务
repository，不能通过把输入草稿写入 NVS 或观察测试页重启来替代。

## 2. 数据来源与许可

拼音读音来自 MIT 许可的
[`mozillazg/pinyin-data`](https://github.com/mozillazg/pinyin-data)，固定到提交
`923b108dc5d45dee061324c011b478fb649f8b73`。项目保存了原始许可、文件哈希、
用途和三个补充字的来源，详见
[`third_party/pinyin-data/PROJECT-NOTICE.md`](../third_party/pinyin-data/PROJECT-NOTICE.md)。

资源选择如下：

- `kMandarin_8105.txt`：主要读音来源。
- `kHanyuPinlu.txt`：只作为显式层级和频率档位后的稳定常用字回退，不把它
  解释为数值词频。
- `gb2312_fallback.txt`：补齐一级字表中 `矽`、`硷`、`磺` 三字。

排序 v2 另使用 Unicode Unihan 15.1.0 的 `kFrequency`。该属性只把字粗略分为
1–5 档，来源是历史繁体中文 USENET 数据，且 Unicode 将其标为 provisional；项目
因此只把它作为层内排序信号，不宣称它是现代简体中文语料。固定版本、源压缩包
SHA-256、过滤结果和许可证见
[`third_party/unicode-unihan/PROJECT-NOTICE.md`](../third_party/unicode-unihan/PROJECT-NOTICE.md)。
较新的 Unihan 版本已不再发布该字段，因此不能无审查地把固定版本改成 latest。

可编辑的 `assets/chinese-input/candidate-priority.tsv` 定义两种显式层级：15 个基础
高频字优先，其次是孕期记录和设备操作场景字，其余字最后。层内依次按
`kFrequency` 档位、词表稳定顺序、`kHanyuPinlu` 集合和 Unicode 码点回退。
这是一套面向本产品的单字候选排序，不等同于通用输入法语言模型。

## 3. 生成和运行时设计

执行：

```bash
python3 tools/fetch_unihan_frequency.py
python3 tools/generate_pinyin_index.py
```

生成器完成以下校验：

1. 从 GB2312 双字节区域精确构造一级汉字集合，并断言为 3,755 字。
2. 将带调读音做 Unicode 规范化，去掉声调并将 `ü` 统一为 `v`。
3. 校验 3,171 条 `kFrequency` 提取项、所有词表字及其项目实际采用的读音。
4. 计算场景词表的候选位置；任何字位落到每页 8 个候选之外都会使生成失败。
5. 拒绝缺失读音和超过 `uint16_t` 的键、候选偏移。
6. 生成 `src/ui/assets/pinyin_index_data.{h,cpp}`；生成文件不可手改。

`src/ui/pinyin_candidate_index.*` 接收一个完整、全小写、无声调的 ASCII 单音节，
最长 6 字母。接口对排序键执行二分查找；未知键、空值、大写、数字或超长输入
均返回空视图。索引条目由三个 `uint16_t` 组成，编译期断言其大小为 6 字节。

当前生成统计：

| 指标 | 数值 |
| --- | ---: |
| 覆盖汉字 | 3,755 / 3,755 |
| 拼音键 | 394 |
| 候选引用 | 3,757 |
| 拼音键字符串 | 1,674 B |
| 生成资源逻辑大小 | 11,552 B |
| 最大单键候选 | 54 |
| 排序规则版本 | 2 |
| 场景词字位首屏命中 | 122 / 122 |
| 场景词最差候选位置 | 5 |

生成的 C++ 源码文本为 48,848 字节，不等于固件资源占用。ESP32-S3 release
对象实测候选、条目和键表 `.rodata` 为 11,553 字节（比逻辑结构多一个 C 字符串
尾零），连同 30 字节统计常量共 11,583 字节。资源尚未被产品页面引用时，链接器
会将其回收，因而本轮四个最终固件大小未增长；最终固件增量必须在输入器接入后
重新从 ELF/Map 实测。

## 4. 字体与编辑状态预算

输入字库使用 SIL Open Font License 1.1 的
[`Noto Sans CJK`](https://github.com/notofonts/noto-cjk)，固定到提交
`f8d157532fbfaeda587e826d4cd5b21a49186f7c` 的 `NotoSansSC-Medium.otf`。
原始字体不提交；下载脚本校验 SHA-256，许可证与来源见
[`third_party/noto-cjk/PROJECT-NOTICE.md`](../third_party/noto-cjk/PROJECT-NOTICE.md)。

重新生成：

```bash
python3 tools/fetch_chinese_input_font.py
python3 tools/generate_chinese_input_font_assets.py
```

生成器验证字体哈希、3,755 个一级汉字均非缺字框，并输出独立的 Medium 18 px
和 24 px 一位图 strike。它不替换现有产品 UI 字体，只供中文输入页面显式使用。

实际结果：

| 资源 | 逻辑大小 |
| --- | ---: |
| 18 px 位图 | 204,945 B |
| 24 px 位图 | 272,221 B |
| 两档 3,871 字形元数据 | 123,872 B |
| 输入字库合计 | 601,038 B |
| 拼音索引 | 11,552 B |
| 字库与索引合计 | 612,590 B |

ESP32-S3 对象实测两档位图和字形元数据为 601,038 B，两个 strike 描述与指针
另占 40 B，因此字库只读数据合计 601,078 B。字库和编辑器尚未被产品页面引用，
链接器会回收它们，
所以当前最终固件大小没有变化；页面接入后必须重新测量最终 ELF。

执行：

```bash
python3 tools/report_chinese_input_budget.py
```

该脚本依据旧有 Medium 18 px 与 24 px 字形的真实位图密度，曾估算 GB2312 一级
3,755 字加 95 个可打印 ASCII 字形。两档字形估算合计 572,501 字节，加 20%
余量为 687,001 字节。加入常用标点和缺字标记后的实际独立字库为 601,038 字节，
比含余量估算少 85,963
字节；该估算脚本继续作为回归上界参考。

`ChineseTextEditor` 已实现固定容量状态，ESP32-S3 实测对象大小 814 B：正文 801 B（800 UTF-8 B 加终止符）、
拼音 7 B（6 字母加终止符）、两个 `uint16_t` 计数和两个 `uint8_t` 状态；不使用
堆内存。它严格校验 UTF-8，支持末尾追加/删除、拼音组合、每页 8 个候选、翻页
和选字，达到 200 Unicode 字符或 800 B 时明确返回 `Full`。候选直接引用 Flash，
不复制整页。当前状态只支持末尾编辑，不包含光标选区或撤销。

## 5. 与存储合同的关系

中文标题和正文作为 UTF-8 记录字段保存，与 FAT 物理文件名分离。S1 继续使用
程序生成的 ASCII 8.3 路径，不启用 FAT 长文件名；同时维持最多 4 个打开文件、
单 storage worker 和深度 8 的有界请求队列。拼音字典编译进固件，不从卡上临时
加载，因此不会占用文件句柄或让拔卡破坏离线输入候选。

## 6. 输入页面与真机测试入口

`src/ui/chinese_input_page.*` 使用专用 18/24 px 输入字库渲染正文、拼音、候选、
计数和按钮。横屏使用 10/9/7 字母布局，竖屏使用 6 列五行布局；两种方向均固定
每页 8 个候选。所有可见控件和触摸命中复用同一个矩形函数，主机测试逐一校验
控件中心、屏幕边界、最小 48×48 触摸目标及控件互不重叠。
