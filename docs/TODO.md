## 2. 共享设计

本节保留存储与卡生命周期的设计合同；四应用合同以需求 v1.4 和上方 V1 任务为准。

### 2.1 存储与资源所有权

| 对象 | 目标所有者 | 设计 |
| --- | --- | --- |
| SPI2 主机和两设备 CS | `board_shared_spi.*` | 从显示层抽出总线初始化；统一初始化、恢复及生命周期 |
| MicroSD 挂载/卸载/卡检测 | 新 `devices/sticky_sdcard.*` | SDSPI + FatFs；卡状态事件和 generation；不拥有或释放整个 SPI2 |
| 文件读写与提交 | 新 `storage/sd_storage_service.*` | 单个存储工作任务，有界请求队列；所有用户数据 I/O 由此执行 |
| 业务记录 | `pregnancy/services/*_storage.*` 及新增 repository | 复用领域校验，以 SD 后端替换 NVS 业务后端 |
| 页面和用户动作 | `apps/*`、`ui/*` | 接收状态快照和提交结果，不直接打开文件或持锁刷新 |
| 深睡与全局调度 | `app/sticky_app.*`、`system/scheduler.*` | 协调写卡和显示，完成关闭握手后关电 |

该设计中的 SPI2 改造已实现：初始化由 `board_shared_spi_init()` 统一拥有，显示与 SD 复用；并发和故障场景仍按对应实机矩阵验证。

### 2.3 卡上数据布局（拟定）

物理应用路径冻结为 `/sdcard/PREGJNL/`，所有卡上目录和文件均使用大写 ASCII 8.3 名称，不依赖 FAT 长文件名；界面和文档中的用户标题不直接作为路径。首版每卡一个数据集，manifest 保存 dataset_id、schema 和提交代次。

| 物理相对目录 | 内容 |
| --- | --- |
| `MANIFEST/` | `MNF000A.JSN` / `MNF000B.JSN` 双代数据集身份、schema、提交代次和 CRC32 |
| `PROFILE/` | 孕期档案、语言/时区/声音偏好 |
| `RECORDS/` | 各领域有界、不可变的记录对象与版本 |
| `JOURNAL/` | 带长度、事务 ID、校验的提交/恢复日志 |
| `SNAPSHOT/` | 分代索引快照；损坏时可从有效记录重建 |
| `MIGRATE/`、`LEGACY/` | NVS 导入报告、来源指纹、旧胎动数据 |

每份结构化记录带 schema_version、id、revision、长度和校验和；建议使用有界 UTF-8 JSON 封装并明确校验所覆盖的原始字节，避免不同序列化顺序影响校验。音频校验单独记录。是否压缩在性能验证后决定，不作为首阶段依赖。

目录布局不能被解释为全部文件同时加载进内存；列表分页，图表只加载指定日期区间。打开文件数、路径长度、JSON 最大字节数和请求队列深度均设上限。

### 2.4 提交和恢复协议

1. 检查卡可写、dataset_id 和挂载 generation 与请求一致，预留新记录及恢复工作区。
2. 写入新版本临时记录，检查短写和错误；执行同步、关闭并回读校验，保留原有效版本。
3. 追加关联新版本的提交记录并同步。同一逻辑事务的多项变更只有在完整提交日志写入后才可见。
4. 更新派生索引或在启动时重建；向 App 返回成功，App 才更新已保存状态及提示音。
5. 按安全检查点回收无引用旧版本，保留可恢复上一代。

恢复读取最后有效快照并重放完整校验通过的事务，忽略截断尾部；未知 schema 禁写。删除也提交 tombstone，迟到结果不得复活对象。

FAT32 不是事务文件系统；`rename`、`fsync` 和回读校验不能保证劣质卡或任意时刻拔卡绝不损坏。双代与日志降低应用层损坏风险，必须通过电源故障注入验证，并保留整目录离线备份流程。遇到文件系统级损坏进入错误态，不自动格式化。

### 2.5 卡状态与数据隔离

状态至少包括：Absent、Mounting、ReadyReadWrite、ReadyReadOnly、Full、Fault、Ejecting、Unmounted；状态变化通过事件通知协调器。

- 每次挂载赋新 generation；任何旧文件句柄、异步结果和 pending write 均须重新校验。提交请求使用 dataset_id + 事务号 + revision 做幂等判定。
- 换卡立即取消旧任务，清空业务缓存；同一卡重新插入也重新校验，不能复用旧句柄。
- 无卡不回写 NVS。只读时仅浏览有效记录，不执行写入。
- 安全卸载/深睡：禁止新任务 → 排空写队列并同步 → 关闭文件/卸载 → 绘制最终状态并完成显示关闭 → 关闭卡电。
- 如同步/卸载失败，正常睡眠请求返回错误并保留故障状态；临界低电只能尽力终止，记录该次可能未保存，不声称成功。相关超时必须有上限。
- 首版只测试单分区 FAT32；不支持的卡显示准备说明。初始化只创建应用目录，不执行格式化。

### 2.6 内置存储例外与迁移

用户配置以卡为唯一持久来源；内置存储只保留固件、静态资源及校准数据。临时启动语言在未挂卡时使用固件默认值。

迁移顺序：识别旧 NVS 版本 → 用户确认目标卡 → 只读载入并验证旧记录 → 转换为 SD schema → 写卡回读 → 提交迁移完成标志 → 新版本停止向旧 NVS 写业务数据。来源指纹与原记录 ID 防重复，迁移中断可继续。

已存在业务数据的卡不自动合并旧 NVS；保留并提示选择空卡或另行导入。迁移完成后用户可明确清除旧副本，清除完成标记必须防止下次启动重新导入。胎动已调整为 V1 核心应用，由 V1-03/04 将旧会话校验导入正式 SD repository 并保留普通入口；不复用或重编号旧 Kicks ID。
