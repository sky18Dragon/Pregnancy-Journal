## 1. 已确认的版本范围

**V1 首版完成体重、胎动、设置、孕周四个应用，采用手动操作、离线使用和 MicroSD 持久化。**

| 版本 | 应用与能力 | 交付要求 |
| --- | --- | --- |
| V1 | 体重、胎动、设置、孕周；共享显示、触摸、按键、RTC、电量、方向和休眠；卡存储、恢复、迁移与备份 | 四应用可独立完成核心操作，数据保存和异常反馈可靠，通过对应实机验收后交付 |
| V2 | 提醒、产检与到期提醒、习惯、备忘、录音、离线分类、待整理/核对、配网/授权、Coze 语音转文本 | 继续保留 V1 四应用；复用已完成的存储基础和原型，完成下一版本业务与语音联网闭环 |
| 后续独立规划 | 手机同步、报告、云备份、OTA、家庭消息等 | 不作为 V1 或本次 V2 的新增必需范围 |

原 v1.3 的语音、联网、习惯和备忘设计移到 [V2-PROJECT-SPEC.md](V2-PROJECT-SPEC.md)。V2 的分类准确率、录音试听、云转写时延、供应商条款及 A01–A26 验收不作为 V1 发布门槛。

此前的“隐藏胎动普通入口”和“缺少语音闭环只能交付原型”不再适用于 V1。提醒与产检虽然已有代码，仍须从 V1 导航、孕周快捷入口和业务提醒调度中退出；已有数据须保留，不能通过范围调整自动清除。

已确认的 MicroSD 决策继续生效：所有新增用户记录与偏好保存到卡，不降级写入 NVS/Flash。V1 必须补齐胎动的 SD repository 和旧 NVS 迁移。固件、静态内容、设备身份/密钥及校准数据属于内置存储允许的例外。

## 2. 产品定位

设备是 Seeed Studio reTerminal Sticky 上的离线孕期记录工具。首版帮助用户查看孕周、手动记录体重、数胎动及管理设备与数据卡，不提供诊断、治疗、普遍适用的医疗阈值或紧急报警保证。

单设备、每卡一个数据集；英文和简体中文界面；支持 800×480 横屏与 480×800 竖屏，并正确转换四个持握方向的触摸坐标。只读卡可浏览已验证记录，创建、编辑、删除必须有可写且已选择的有效数据集。

## 4. 四应用交付要求

### 4.1 孕周

- 首次设置设备时间、确认后的预产期或末次月经日期；可修改并校验真实日历日期。
- 首页显示孕周/孕天、阶段、预产期倒计时、40 周进度和既有周插图；宝宝/妈妈页使用离线内容。
- 保持周内容 1–40、插图 6–40 的既有边界及明确回退，不因超出范围访问非法资源。
- 不展示未交付的产检预约、待整理数量、录音或联网入口。
- 档案经统一 SD repository 保存；缺卡、只读、损坏、换卡与迟到结果有明确处理，不展示上一张卡的档案。

### 4.2 体重

- 手动创建每日体重，显示和编辑 kg/lb；保留身高、基线及数值变化，数值只用于个人记录。
- 提供按日历筛选的 7/30 日趋势，缺失日期不补零；支持基础历史查看、编辑和删除。
- 同日记录替换须确认；保存完成后才更新已保存状态；删除后图表和最新值保持一致。
- 沿用原任务的 366 条目标容量，需与 SD 恢复索引、分页和日志容量共同实现并验证；未完成前不得宣称支持。
- 不使用固定增重或周增长阈值输出正常/异常结论；满额不静默覆盖已有记录。

### 4.3 胎动

- 保留普通应用入口和既有 `StickyAppId::Kicks` 数值，不作为仅 legacy 数据管理入口。
- 可开启会话、计数、撤销、结束保存或取消；保留 400 ms 防误触、RTC 时段和 60 分钟有界会话。
- 提供今日会话/次数/时段汇总与最近七个日历日的记录趋势，缺失数据不补成医学结论。
- 首版沿用 42 个会话的容量基线；任何扩容另做资源预算。容量与满额行为须在发布说明中明确。
- 增加有版本、校验、稳定 ID/revision 的 SD payload 和 repository store，使用 shared storage worker。新会话不再写 `kicks` NVS；保存失败不得显示成功。
- 旧 NVS 会话只读载入、校验、幂等导入和逐条回读；用户确认清除前保留源副本。导入中断、损坏和目标冲突不能静默覆盖或丢失。
- 不作正常/异常评分，不外推全天胎动数；保留现有联系医护提示，发布前完成内容审核和双语表达检查。

### 4.4 设置

- 语言、RTC 时间、孕期档案入口、设备/电量信息、电子纸清屏。
- MicroSD 状态、容量、数据集身份、显式初始化、安全取出、旧数据导入、卡上应用数据删除与备份说明。
- 无卡提供存储帮助与基础设备信息，不新建用户档案、不使用 Flash 保存用户数据；只读卡明确禁写。
- 设备重置与删除当前卡的 `PREGJNL` 保持独立说明和确认；不格式化卡、不删除其他目录。
- 胎动的旧副本清除只有在成功导入并回读核验后开放；范围缩减不授权清除提醒/产检等旧数据。
- 配网、云授权、转写配置移至 V2，不作为 V1 用户设置的必需入口。已有凭据数据保持原有保护和删除边界。

## 5. 共享运行与存储约束

### 导航、提醒与电源

- Launcher 仅展示四个 V1 应用；保留顶部单击、双击返回孕周、底部滑动及侧键休眠手势。
- 应用仍通过 registry 注册，由协调器负责切换、显示所有权、输入和睡眠，不添加应用之间的直接调用。
- V1 停用提醒/产检业务唤醒和响铃，即使旧卡保存了未完成预约或提醒也不触发。只隐藏入口不算完成范围收敛。
- 日常显示维护、低电处理、RTC 和睡眠唤醒继续属于共享基础，不随业务提醒延期而删除。
- 普通稳定页沿用 60 秒电池闲置休眠，设置稳定页三分钟；日期/时间/体重编辑与胎动会话按现有规则保护未提交操作。
- 深睡前关闭新存储准入、完成已接纳工作、同步并卸载成功才关卡电；失败须有界报错，唤醒后重新挂载和恢复。

### 容量、提交与迁移

- 复用板级共享 SPI2 和唯一 storage worker。页面只渲染状态，不挂卡、读写文件或刷新面板。
- 复用 `/sdcard/PREGJNL/`、ASCII 8.3 物理路径、dataset_id、mount generation、不可变对象和完整日志提交才可见的协议。
- 原 64 槽恢复索引不足以承载 366 条体重与 42 个胎动会话；候选已扩展到 1,024 槽，容量验收仍须覆盖档案、偏好、保留的旧领域记录和删除标记。
- 扩容需处理索引/快照一致性、分页、任务栈/堆预算、日志段上限与 tombstone 长期占用；不能只修改业务数组大小。
- 任何新 schema 或 repository kind 不得改动现有持久枚举数值；未知高版本数据集禁止写入。
- 保留现有已验证 SD 数据和旧 NVS 记录。提醒/产检迁入的记录仍可随完整目录备份，不激活其调度，不自动删除或重解释为胎动。
- 重启、短写、删除、换卡与迁移重试保持已提交数据可判定；不自动修复损坏卡、不格式化。
- 备份为安全卸载后复制完整 `PREGJNL`，使用 [备份校验与恢复流程](S1-BACKUP-RECOVERY.md)。

### 显示与内容

- 复用 `ui_tokens.h`、`prototype_ui.*` 与双语/字形生成机制，视觉与命中几何同源。
- 首版交互页使用黑白；稳定入口/方向变化全刷，小变更局刷，重复更新进行完整清理。
- 不依赖 V2 的中文自由文本编辑器、录音模型或网络服务才能完成四应用操作。
