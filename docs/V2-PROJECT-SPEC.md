# 孕期墨水屏伴侣 — 第二版本扩展需求（V2）

需求来源：原 v1.3（2026-09-25）；分期调整：2026-10-10。状态：V2 扩展方案，尚未实现完整产品闭环。

当前首版范围以 [PROJECT-SPEC.md](PROJECT-SPEC.md) v1.4 为准：体重、胎动、设置、孕周四个应用。本文保留提醒、产检、习惯、备忘及语音转写的下一版本设计；本文的 P0、验收编号 A01–A26 和语音/联网发布门槛只适用于 V2，不阻塞四应用首版。开发方案与证据见 [TODO.md](TODO.md)。

V2 继续保留 V1 的四个核心应用；涉及隐藏胎动入口的旧方案已取消。本文中的 Coze 参数和外部资料是 2026-09-25 的设计核对记录，实施前须重新验证，不表示当前接口或条款已再次核实。

已确认决策：语音文件及设备用户数据统一持久化到 MicroSD 内存卡。卡可写且已选择有效档案是创建和修改用户数据的前提；不降级写入内置 Flash。

已确认决策：联网转写 V2 支持 Coze（扣子），通过统一厂商适配接口预留其他服务商。V2 按中国区 Coze API 设计；其他区域须单独配置和验证，不自动跨区发送音频。

输入：用户提供的《孕期墨水屏伴侣--产品需求文档.md》，结合当前 Pregnancy Journal 固件与 reTerminal Sticky 硬件资料整理。

本文定义 V2 扩展目标。当前工作区固件版本仍为 2.0.0；V1/V2 是交付阶段名称，不重置固件版本号。新增语音、联网、备忘和习惯功能均为待实现需求，本文不表示它们已经开发或验证完成。文中的容量、时延、阈值和默认时间如标为“建议”，均为可测试的设计目标，需通过原型与实机验证后冻结。

## 1. 产品定位与目标

### 1.1 产品定位

一款放在床头或家中固定位置的孕期记录设备：按住说一句，先保存到设备内存卡；连接已配置的家庭网络后转成文字，重要数字和时间经用户核对后正式入账。

核心价值是降低记录摩擦、集中管理体重与日程，并在不打开手机的情况下看见当天重要信息。设备在插入可用内存卡时支持不联网使用；语音内容的精确转写需要网络与用户授权。

原稿中“记录断续”“专用设备优于手机”等市场洞察作为待验证假设。首轮用户测试应验证记录完成率、重复使用意愿与床头场景适配性，不把这些假设写成已证实结论。

### 1.2 用户与场景

| 用户任务 | 典型情境 | 产品应做到 |
| --- | --- | --- |
| 随手留下一条记录 | 刚称完体重、双手不便打字 | 按住录音并确认类别；离线也能保存 |
| 安排下一次产检 | 刚确认预约信息 | 手动立即建立提醒，或保存语音待核对；说明未核对语音尚未设提醒 |
| 记录日常习惯 | 每日固定时段 | 一次配置后离线提醒，完成与跳过分别记录 |
| 记住要问医生的问题 | 睡前突然想到 | 留下一条短备忘，之后可查阅、修正、删除 |
| 查看近期变化 | 早晨起床或准备就诊 | 一眼看到孕周、今天日程和近期体重趋势 |

V2 使用假设：单设备、单孕期档案、主要录音语言为普通话；继续兼容现有中英文界面。英语和方言语音不作为 V2 准确率承诺。

### 1.3 成功标准

- 内存卡正常时，无网用户可完成体重、产检、习惯和备忘的手动创建及查看。
- 语音先可靠保存；“已保存”不能代表“已转写”或“提醒已生效”。
- 分类错误可以在现场纠正；转写错误可以在入账前修正。
- 断电、断网和重试不会把一段语音变成多条重复业务记录。
- 不用颜色、持续动画或频繁刷新表达必要状态。
- 产品仅提供记录和日程管理，不提供诊断、补剂剂量或个体化医疗决策。

## 2. 对原稿的设计完善

| 原稿中的问题 | 本版建议 | 原因 |
| --- | --- | --- |
| 要求离线完整使用，但手动输入为 P1 | 基础手动创建、编辑、删除提升为 P0 | 语音转写不可用时仍须完成核心任务 |
| 分类确认后联网直接归位 | 分类占位可立即归位；关键字段核对后才入账 | “体重”类别正确不代表“56.2 kg”识别正确 |
| 任意语句本地关键词预判 | 普通话四类命令词原型验证；不确定时提示手选 | 离线命令词识别不等于任意语音理解 |
| 声音或灯光即时反馈 | V2 使用蜂鸣器和持久屏幕状态；灯光为待验证增强项 | 现有充电指示灯不能假定可作为业务灯控制 |
| 按孕周自动生成产检计划 | 自动生成待确认建议，确认具体日期时间后启用提醒 | 区分参考计划与用户已确认的预约 |
| 历史回溯全部为 P2 | 本模块历史列表与编辑为 P0，跨模块时间线仍为 P2 | 月趋势、纠错和查重需要基础历史访问 |
| 胎动纳入四应用首版 | V1 完成 SD 存储和旧记录迁移，V2 继续保留普通入口 | 保持已确认的核心应用范围 |

以上为原方案的设计背景；四应用首版的优先级及发布门槛以 PROJECT-SPEC.md v1.4 为准。

## 5. 信息架构与页面设计

### 5.1 页面入口

| 页面 | 一级内容 | 主要操作与返回 |
| --- | --- | --- |
| 孕周首页 | 孕周、进度、宝宝类比、最近预约/今天习惯、待整理数量 | 录音、全部功能；点日程进入对应详情 |
| 全部功能 | 体重、产检、习惯、备忘、待整理、设置 | 点击进入；关闭回到原页 |
| 录音流程 | 准备、录音中、类别确认、保存结果 | 停止、确认、换类、重录、取消 |
| 待整理 | 待分类、待转写、待核对、失败项目 | 分类、核对、修正、重试、删除 |
| 体重 | 最新值、7/30 日图、历史列表 | 新增、详情、编辑、删除 |
| 产检 | 待确认建议、已预约、已完成 | 确认预约、改期、完成、取消 |
| 习惯 | 今日待办、已完成、规则管理 | 完成、稍后、跳过、编辑规则 |
| 备忘 | 时间倒序列表与详情 | 新建、编辑、删除 |
| 设置 | 档案、时间、声音、网络、隐私、存储、屏幕 | 各设置保存后回上一级 |

待整理在首页展示数量，并在所属模块展示“语音待转写/待核对”占位。占位与收件箱引用同一条任务，不能产生两条记录。

### 5.2 首页布局

- 横屏 800×480：左侧突出孕周与进度，右侧为宝宝类比图和最近日程；底部为录音与全部功能入口。
- 竖屏 480×800：按孕周、进度、类比图、日程摘要、底部操作依次排列。
- 标题区固定展示日期、电量、联网/离线、待整理数量。图标带简短状态标签，不把在线作为使用前提。
- 当天多个事项只显示摘要与数量，详情在独立页面分页展示。
- 孕周超出内容覆盖范围时如实显示日期和“暂无对应周内容”，不展示不匹配的类比图。

### 5.3 视觉与墨水屏规范

沿用 [DESIGN.md](DESIGN.md) 和 `src/ui/ui_tokens.h`：24 px 安全边距、主要触控区建议至少 56×56 px，任何按钮触控区不小于 48×48 px；正文 18 px、标题 24/28 px、主数字 52/56 px。

- 黑白为主，使用边框、文字与反色表示选中/失败；不依赖灰度或颜色理解状态。
- 每页一个主要动作；长文分页，避免为了塞满一屏缩小字体。
- 报错显示在操作区域附近，说明失败对象与下一步；成功状态保留至离页，不使用短暂 toast。
- 录音开始、结束、类别确认各刷新一次；不绘制实时波形，不每秒刷新倒计时。
- 录音和类别确认阶段锁定方向；退出流程后应用已稳定的新方向，防止操作按钮移动。
- 首次进入、方向切换及清理残影使用全刷；局部字段变化使用局刷，沿用并验证现有定期全刷策略。
- 静音模式显示明确的“正在录音/已保存”，并提供“点击开始—点击停止”方式。录音就绪时延必须在静音实机测试中单独验证。

## 6. 核心交互流程

### 6.1 首次使用

1. 检查内存卡：已初始化的卡加载档案；新卡经用户确认创建应用目录；无卡、只读或不支持的文件系统进入存储说明页，不自动格式化。
2. 选择语言，设置设备时间和时区；V2 默认建议为 Asia/Shanghai，可修改。
3. 输入已确认的预产期，或选择末次月经日期；说明日期可后续修改。
4. 档案成功写卡后进入首页，手动记录可用。
5. 首次使用语音时介绍操作、音频容量和“本地保存后待转写”的含义。
6. 联网转写为单独可选授权：展示服务提供方、发送数据、保留策略与关闭方法，再配置 Wi-Fi；可跳过。

建议 P0 通过设备临时 Wi-Fi 配网页完成网络凭据输入，验证可连接家庭网络后关闭配网热点。此过程不要求开发配套手机 App；热点口令、绑定令牌和超时退出属于实现验收项。设备保留“忘记网络/重新配网”。

### 6.2 录音与分类

建议保留现有单击顶部键切换启动器、双击回首页；新增顶部键长按进入录音。建议识别阈值 600 ms，松开结束；长按发生后不得再触发单击或双击。顶部键启动/唤醒与录音手势是否冲突须实机验证。

1. 唤醒后先完成麦克风与存储准备，再给出就绪反馈；不宣称保存了就绪前的语音。
2. 用户可说“体重，今天五十六点二公斤”。建议引导以“体重/产检/习惯/备忘”开头，但不强制用户每次正确说出。
3. 松开或点击停止后，先完成音频临时文件封口，再展示类别建议。
4. 四类标签可切换；低置信度或多个类别冲突时显示“请选择分类”，不自动归类。
5. 点击“保存到体重”等按钮，提交分类与音频索引。只有持久化成功才反馈“已保存到内存卡，待转写”。
6. 未确认分类就离开时，保留为“待分类草稿”；后续可继续或删除，不自动上传。

建议单条上限 30 秒，到上限自动停止并进入分类确认；过短、静音或采音失败时提示重录或手动填写。一条录音对应一个分类和一条业务候选；多事项语句提示拆开记录，不静默创建多条任务。

### 6.3 即时反馈语义

| 事件 | 反馈 | 屏幕文案 |
| --- | --- | --- |
| 麦克风真正就绪 | 短提示音 | 正在录音，松开结束 |
| 录音停止 | 与保存成功不同的短音 | 请确认分类 |
| 分类和音频成功落盘 | 两声短音 | 已保存到内存卡，待转写 |
| 存储或录音失败 | 明确失败音型 | 未保存：具体原因；重试/手动记录 |
| 结构化内容确认成功 | 轻提示音 | 已记录；预约另显示提醒是否开启 |

蜂鸣器用于提示音，不承诺语音播放或 TTS。按当前硬件不把音频回放列为 V2 依赖。静音时关闭提示音，但持久屏幕结果始终存在。

### 6.4 联网转写与入账

已确认分类 → 等待网络 → 上传 → 转写 → 本地解析候选字段 → 待核对 → 用户确认 → 业务记录提交。

- 云端职责限定为语音转文字；类别保持用户选择。本地从文本提取日期、单位和数字作为候选，解析不确定时保留原文并要求填写。
- 体重、产检、习惯必须在用户核对后生效。未核对的产检语音显示“尚未设置提醒，可手动补录”。
- 备忘转写完成后可自动填入原占位，标记“转写未校对”，不触发日程；用户可编辑或改类。
- 无结果、空文本、多个数值、日期歧义均进入可处理状态，不猜测正式记录。
- “昨天”按录音时的日期/时区解释，不按联网日解释；“周五”存在歧义时展示完整日期供确认。
- 转写结果返回不抢占正在录音、输入或提醒确认页；只更新待整理数量。
- 用户手动补录时可选择“用于完成这条语音”，关联相同任务并停止重复入账；已在传输的旧响应须被忽略。
- 改类别需用户操作；云端不得覆盖已确认类别、已经修正的文本或更新的记录版本。

### 6.5 Coze 首发与厂商扩展

- V2 使用 Coze 音频转写 API，云端仅返回文字；本地继续负责分类确认、字段解析和入账核对，不让厂商自动修改业务记录。
- 设备对接统一转写网关，网关通过 `TranscriptionProvider` 适配 Coze。Coze 服务令牌由网关管理；卡上只保存用户授权、厂商配置和设备访问凭据的加密封装。
- 用户在启用时看见实际厂商、服务地区和数据政策。增加新厂商只需新增适配器和配置并通过合同测试，无需修改业务页面、SD 记录模型或核对流程。
- 每次任务尝试固定 provider_id、配置版本、授权版本；切换厂商只影响后续新任务。旧任务迁移需用户确认，保留原任务关联并防止重复入账；不在失败时静默转发给其他厂商。
- 统一接口区分同步结果与异步任务；查询、取消和删除是能力声明，不假定所有厂商具备。网关取消与“供应商已停止处理/已删除数据”分别显示。
- Coze 凭据、费用、实际可用权限和保留条款仍需联调验证；确定厂商不等于已开通服务。后续厂商具体接入为扩展任务，V2 交付统一接口与 Coze 适配。
- Coze 接口细节、能力声明和错误处理见 [TODO.md](TODO.md) 的 2.7 节。

## 7. 业务功能要求

转写厂商的选择和调用规则见 6.5；下列业务规则不随厂商改变。

### 7.1 孕周与档案（F01）

复用当前孕周计算与静态内容。用户可调整日期来源和预产期；修改前后日期并排核对。修改档案只重新计算未确认的计划建议，不能自动移动已预约产检，也不能改写历史记录日期。

### 7.2 体重（F05）

- 手动字段：日期、体重、单位、可选短备注；日期默认今天且可更改。数值保留一位小数，界面始终显示单位。
- 持久化统一为 0.1 kg；lb 转换后展示最终保存值，输入限值作为技术校验，不描述为健康范围。
- 语音候选展示原文、日期、数值和单位，逐项修正后保存。缺单位时明确提示用户选择，不能从裸数字暗中推断斤/公斤。
- 同日已有记录：展示旧值与新值，选择替换或取消；同步重试不能绕过此确认。
- 图表提供最近 7/30 个日历日。缺记录日留空，不补零、不当作体重下降；不足两点时只显示点和日期。
- 纵轴标注单位与范围，横轴标注时间；仅显示相对上次和基线变化，不给出医疗评价。
- 历史列表支持分页、详情、编辑和删除。删除后更新图表；容量满时提示管理历史，不自动丢弃最早记录。

### 7.3 产检（F06）

- 预约字段：名称、完整日期、时间、可选地点/备注、提前提醒与到时提醒开关。
- 提前提醒建议默认 1 天；首次保存时明确展示，用户可关闭。新增预约不得默认使用未经用户确认的 09:00。
- 自动计划仅生成“待确认建议”：孕周窗口、项目名称、来源地区、来源版本；缺少已审核模板时仅提供手动预约，不生成虚构节点。
- 用户确认实际日期和时间后转为“已预约”，进入本地提醒调度。改变模板只影响未确认建议。
- 状态：待确认建议、已预约、已完成、已取消；“已过期”是时间条件，不自动等于完成。
- 改期后取消旧提醒实例，生成新实例；删除/取消预约也取消关联提醒。

本版不直接列出产检项目或医学孕周表。内容负责人须选定适用地区的权威规范，记录版本并完成专业审核后导入模板。

### 7.4 习惯（F07）

- 支持自定义名称、每日或指定星期、一天最多三个时间点、开始日期、可选结束日期。
- 早/午/晚必须对应具体时刻。建议初始值 08:00、13:00、20:00，创建页可改，并明确这些只是设备日程默认值。
- “补剂”仅是用户自建项目名称，设备不建议成分、剂量或服用频次。
- 完成记录绑定某天某个提醒实例；同一实例反复点击只记一次。
- “稍后”建议延后 15 分钟且每实例最多一次；“跳过”仅影响本次，“暂停”影响规则未来实例。
- 修改规则只影响未来实例，历史完成记录不重写。跨午夜的稍后提醒保留原实例身份。

### 7.5 备忘与离线文字输入（F08）

- 备忘字段：创建时间、内容、来源、转写校对状态；建议正文最多 200 个 Unicode 字符。
- 列表按记录时间倒序；显示摘要、时间与“待转写/未校对”标记。详情可分页、编辑、删除。
- P0 手动中文输入采用本地拼音候选键盘，另提供数字、英文、常用标点；候选翻页与删除均可离线执行。词库容量与字体覆盖须原型验证，不把仅数字键盘算作文字录入完成。
- 习惯名称、预约标题可复用文本编辑器。V2 不支持富文本、附件、语音播放或由备忘自动创建提醒。
- 删除前显示对象摘要并确认；正在上传的备忘删除后，迟到响应不能使其重新出现。

## 8. 通用提醒与电源策略

### 8.1 提醒行为

- 已确认的预约和习惯由本地 RTC/调度器执行，断网不影响；内存卡须可读取。缺卡/换卡后停用原档案提醒并显示原因，不从旧缓存继续发出可能失效的提醒。
- 同时到期的事项聚合为一张提醒页，分别确认完成；触摸或按键先停止声音，再进行明确操作，停声不等于完成。
- 声音提醒建议最多持续 30 秒；无人处理后保留待办标记，不持续鸣响或无限重响。
- 勿扰时段建议默认 22:00–07:00，可修改；仍显示事项但不发声。静音和勿扰开关对全部业务提示有明确说明。
- 录音期间到期的提醒暂缓声音，结束录音后展示，避免声音污染音频；录音有 30 秒上限。
- 时间手动修改/联网校时后重新计算未来事件；已触发实例不可重复响铃。设备停机期间错过的事项恢复后显示“已错过”，不逐条补响。

### 8.2 联网与睡眠

- 用户授权并保存网络后，可在启动、充电开始以及建议每 15 分钟的待转写检查窗口尝试连接；“回家自动整理”指下次窗口连上已知网络，不使用定位。
- 无待处理任务时不为转写唤醒网络；每个窗口建议连接尝试不超过 10 秒。
- 默认电量不低于 20% 且非低电保护时允许电池上传；低于该值等待充电，并提供状态说明。具体门限由实测冻结。
- 网络窗口不妨碍本地提醒。录音优先于上传：进入录音时暂停下一段传输并尽快释放资源。
- 普通页面延续 60 秒闲置休眠、设置页三分钟策略；录音、关键提交和编辑期间保持唤醒。草稿先安全保存才能休眠。
- 单次上传建议超时 60 秒；失败后释放唤醒锁，按退避重试，不以无限后台任务耗尽电池。

## 9. 数据、容量与故障恢复

### 9.1 音频任务状态

| 状态 | 进入条件 | 后续动作 |
| --- | --- | --- |
| 录音中 | 采音与文件写入已启动 | 停止后校验临时文件 |
| 待分类 | 可恢复音频已封口，但用户未确认类别 | 手选分类或删除 |
| 待转写 | 分类和索引提交成功 | 满足授权/电量/网络条件后上传 |
| 处理中 | 服务已接收任务或正在返回结果 | 查询同一任务，禁止新建重复任务 |
| 待核对 | 文本/字段候选已持久化 | 修正并入账；或删除 |
| 已归档 | 业务记录提交并与任务关联 | 执行原音频保留策略 |
| 可重试失败 | 超时、断网、服务暂不可用 | 显示原因与下次尝试，允许手动重试 |
| 需用户处理 | 未授权、存储不可写、音频损坏、格式不支持 | 分类处理，不无限自动重试 |

退避建议为 1、5、15、60 分钟；连续五次失败后暂停自动尝试并保留手动重试。授权失效应立即暂停并提示重新授权，不能当成网络错误反复请求。

### 9.2 容量建议与计算

音频原型以单声道、16 kHz、16-bit PCM 估算：每秒 32,000 字节，每条 30 秒约 960,000 字节；100 条约 96 MB，不含文件头、索引和工作区。

建议 V2 音频队列上限为 100 条或 128 MiB 音频配额，以先达到者为准（内存卡方案的初始目标，须实测冻结）；待分类、待转写、待核对及仍保留的归档音频都占用容量。开始录音前必须预留完整 30 秒预算及写入余量。剩余不足一条时阻止新录音，并展示“队列已满，可整理/删除或手动记录”。

内存卡是 V2 必需的用户数据存储介质。建议 V2 验证 8–32 GB、单分区 FAT32 的 MicroSD；这是测试范围，不代表其他容量或文件系统已兼容。设备不自动格式化或擦除卡上其他文件。录音配额独立于业务数据空间，建议保留至少 32 MiB 可用空间用于业务提交、索引和恢复；达到录音配额时仍允许有足够空间的手动记录，整卡写入失败则阻止全部数据修改。

内置 Flash 用于固件、静态字体/模型资源和设备底层信息，不作为音频或用户业务数据的备用存储。RAM 仅作运行缓存，不算保存成功。

| 数据 | V2 建议容量 | 满额行为 |
| --- | ---:| --- |
| 体重 | 366 条 | 提示管理历史，不静默覆盖 |
| 产检预约 | 64 条，含已完成 | 明确提示已达上限 |
| 活跃习惯 | 12 个 | 停用/删除后再创建 |
| 习惯执行历史 | 最近 366 天 | 更早历史清理须事先明确告知并让用户启用；默认满额停止新增历史并提示 |
| 备忘 | 200 条，每条最多 200 字 | 提示整理，保留现有内容 |

UTF-8 字节上限、索引开销和写入工作区必须另算；字符数不等于 C 字符数组长度。上述业务容量是分页与性能的建议上限，不由卡总容量直接决定。

### 9.3 内存卡数据范围与使用规则

- 卡上存储：孕期档案、体重、产检、习惯与执行历史、备忘、音频、转写/核对任务、删除标记、语言/时区/声音/隐私偏好、网络配置及用户授权状态。
- Wi-Fi 密码及可撤销凭据在卡上采用设备绑定的加密封装；内置存储只允许设备身份、加密根密钥、射频校准等非用户记录信息。具体密钥方案在开发验证阶段冻结，不能以 SDK 默认 NVS 保存行为绕过此约束。
- V2 卡上业务文件不承诺整体加密。卡可被取出读取，UI 须说明；设备绑定的网络凭据在另一设备上需要重新配网和授权。
- 每张应用数据集具有独立 dataset_id；换卡必须清空旧档案缓存，暂停旧上传/提醒，核验新卡后明确提示“已切换数据卡”。不可把 A 卡的录音结果写入 B 卡。
- 缺卡冷启动只提供存储帮助、基础设备信息和重试，不创建用户档案、不录音；运行时拔卡停止新的读写、上传和业务提醒，清除敏感页面并提示插回原卡。已经发出的云请求按尽力取消处理。
- 只读卡可以查看经过校验的记录，但禁止创建、编辑、完成事项、转写提交和自动提醒（无法可靠保存提醒实例状态）。
- 设置提供“安全取出内存卡”：停止新任务、等待写入结束、同步、关闭文件、卸载后提示可拔卡。建议先安全卸载再拔卡；意外拔卡须受控报错，不能保证损坏卡的数据完整性。
- 卡文件系统损坏时提示电脑备份/修复，不自动格式化；陌生文件保留不动；未知更高版本的数据集禁止写入。
- 深睡前完成卡写入和卸载后再断卡电；唤醒后重新挂载、校验并重建提醒。设备没有插卡时不得承诺提醒可用。
- 备份通过安全卸载后在电脑上复制完整应用数据目录完成；只复制音频不算完整备份。恢复时校验版本、校验和及档案身份，不自动合并不同数据集。

### 9.4 持久化与幂等

- 每条语音持有稳定 task_id、创建时间/时区、分类、确认状态、音频引用/校验、尝试次数、文本、候选字段、record_id 和 revision。
- 音频先写卡上临时文件、同步并校验，再提交带版本与校验信息的索引；确认音只在提交完成之后发出。通过双代记录和恢复日志处理多文件一致性，不能把 FAT 的 rename 当作断电事务保证。
- 同一 dataset_id + task_id 重试复用服务端任务；业务层设置唯一关联，保证多次响应只产生一条记录。
- 入账后再标记任务归档。重启发生在两步之间时，根据关联 record_id 对账，不二次写入。
- 删除使用 tombstone 或等效持久标记，取消任务；迟到的响应按版本/删除标记丢弃。
- 录音中断电：保留上次已经确认的记录；未确认片段标记为可恢复草稿或损坏，不能宣称完整保存。
- 启动扫描孤立音频与索引，修复可恢复项，列出无法恢复的对象。存储失败不能显示成功。

## 10. 隐私与联网边界

- 默认不开启云转写、不后台录音；只在用户明确触发时采音。拒绝云授权后，在卡可写时手动功能及本地语音保存仍可使用，并显示待转写状态。
- 首次上传前展示服务方、音频用途、发送字段、费用/配额及保留时长；不以系统更新或配网同意替代音频上传授权。
- 上传仅包含必要音频与任务标识，不附带完整孕期档案、体重历史或无关备忘。
- 使用 TLS 和可撤销设备凭据；供应商长期服务密钥不能硬编码到客户端固件。
- 日志默认不输出音频、完整转写、Wi-Fi 密码或访问令牌；排查材料需脱敏。
- 云端目标为不用于模型训练、任务完成后删除音频、短期返回结果；这些条款必须由服务选型验证。建议音频完成后 24 小时内删除，失败残留七天内删除；不满足时须重新披露并评审。
- 本地默认在业务记录完成核对并成功提交后删除原音频；未校对备忘与失败任务保留音频，用户主动删除除外。删除文件不承诺闪存取证级安全擦除。
- 关闭云转写会暂停新上传；对已发出的请求按供应商能力发出取消/删除请求，说明已上传数据不可能靠断网自动撤回。
- 敏感内容可在设置中切换首页“仅显示数量”，睡眠前隐藏备忘摘要；不承诺设备访问控制，硬件物理隐私能力另行评估。
- 区分“重置本设备”和“删除卡上本应用数据”：后者须二次确认，仅删除当前确认数据集，不格式化整卡、不删除其他文件；无卡时不得宣称已清除卡上数据。旧 NVS 迁移副本的清除单独说明。电脑备份由用户自行保管，设备不提供云备份。

## 11. 技术可行性约束与待验证项

1. **离线分类**：ESP-SR MultiNet 提供 ESP32-S3 离线命令词能力，但这不能证明 Sticky 能从任意自然表达中准确提取意图。先验证四类短命令词、噪声与无关语句的拒识；失败时仍可手选，自动分类未达标则不得宣称该 P0 已完成。[乐鑫命令词文档](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32s3/speech_command_recognition/README.html)
2. **声音与灯光**：Sticky 有 PDM 麦克风和蜂鸣器；公开资料中的灯为充电指示灯。V2 不依赖可编程业务灯，是否可用须核对原理图和实机。[Seeed 硬件总览](https://www.seeedstudio.com/sticky/docs/en/device-guide/hardware-overview/)
3. **共享总线**：显示与 MicroSD 共用 SPI2。必须统一初始化与仲裁，验证持续采音写卡与显示刷新并发、拔卡和睡眠恢复；录音缓冲耗尽时明确报错而非保存有缺口音频。[Seeed 外设指南](https://www.seeedstudio.com/sticky/docs/en/device-guide/esp-pages/)
4. **有限内存**：识别模型、音频缓冲、TLS、字体和画布并存须测峰值内存；不得仅凭 8 MB PSRAM 判断可行。
5. **字体与中文输入**：当前静态字形表不足以自动保证任意转写与拼音输入覆盖。需定义离线常用字库及缺字显示规则；不能用联网补字破坏手动离线能力。
6. **医学内容**：产检模板由适用地区规范与专业审核决定，源文档、版本、审核者和生效范围缺一不可。未通过审核的模板不发布。

| --- | --- | --- |
| A01 | 插卡、首次不开网 | 完成档案并手动创建四类记录，重启后从卡上查到；新用户数据不写入 NVS |
| A02 | 离线录音 | 分类确认后显示本地保存；重启后音频与分类保持一致 |
| A03 | 语音分类 | 至少 10 人、每人每类 10 句普通话测试；安静近讲四类准确率目标 ≥90%；另含不少于 100 条无关/含混语句并报告错误归类率 |
| A04 | 低置信度 | 无关/多意图输入提供手选；所有类别可改，不阻断保存 |
| A05 | 即时反馈 | 就绪/停止事件提示音 P95 ≤200 ms；保存成功音必须晚于落盘；清楚区分三种音型 |
| A06 | 屏幕反馈 | 停止至类别确认可操作 P95 目标 ≤3 秒；未达标记录实测并优化，不伪报完成 |
| A07 | 入账核对 | “56.2 公斤”转写错误或缺单位时可修正；未确认前不改变图表 |
| A08 | 提醒语音 | 分类确认但未核对日期时不启用提醒，界面明确“尚未设置提醒” |
| A09 | 日期语义 | 跨日才联网的“昨天”以录音时间解释；歧义日期要求确认 |
| A10 | 存储满/只读 | 无覆盖，失败不播放成功音；手动记录在其容量允许时仍可用 |
| A11 | 断电恢复 | 在写音频、提交索引、入账、归档各阶段执行断电注入；已确认记录不丢失、不重复 |
| A12 | 重试与删除 | 重放同任务响应十次只生成一条记录；删除后迟到响应不复活数据 |
| A13 | 本地提醒 | 卡可写时断网与睡眠下已确认事项仍到期提示；校时后不重复响；缺卡/只读卡明确暂停提醒 |
| A14 | 安静场景 | 静音/勿扰无蜂鸣；屏幕结果持续可见；录音期间提醒不污染采音 |
| A15 | 趋势与历史 | 7/30 日按日历筛选；缺失不补零；同日替换需确认；删除后图表一致 |
| A16 | 横竖屏与输入 | 四个方向触控对应；中文输入离线可用；录音中旋转不移动确认按钮 |
| A17 | 网络与功耗 | 超时退出、重试退避、低电暂停有效；记录联网/离线各 24 小时能耗后再确定续航目标 |
| A18 | 旧版本迁移 | 既有孕期、体重、产检、提醒、胎动记录保持；V2 扩展不清除 V1 数据或隐藏胎动核心入口 |
| A19 | 隐私 | 未授权零音频上传；关闭上传后不新发任务；日志不包含凭据和完整转写 |
| A20 | 中文文字与容量 | 200 字边界、长标点、缺字和满额均有明确结果，无截断越界或静默丢弃 |
| A21 | 卡移除/换卡 | 录音、上传、入账时移除受控失败；A 卡结果不得落入 B 卡；卡重插可恢复已提交记录 |
| A22 | 安全卸载与休眠 | 写入同步完成才关卡电；唤醒重新挂载；卸载后不再发出文件 I/O |
| A23 | 损坏/未知格式/清除 | 不自动格式化；未知 schema 禁写；删除仅限已确认数据集，其他文件保留 |
| A24 | 卡备份与凭据 | 完整目录可恢复；异机凭据不可直接复用；恢复授权后不得自动重发旧已归档任务 |
| A25 | Coze 真实转写 | 卡上 WAV 经网关和 Coze 返回文字，核对后写卡；鉴权、限流、非零业务码及空结果均可处理 |
| A26 | 厂商扩展合同 | 用第二个测试适配器覆盖同步/异步/不支持取消；业务页无需改动；切换不静默重发旧任务或重复入账 |

云转写建议在稳定家庭网络下以 30 秒音频、至少 100 次任务测量“提交至待核对”P95，目标不超过 60 秒；延迟和错误率按所选服务实测，不将“精确转写”解释为零错误。

## 13. V2 实施阶段与发布门槛

| 阶段 | 交付物 | 进入下一阶段条件 |
| --- | --- | --- |
| M0：可行性验证 | MicroSD 挂载与共享 SPI、采音写卡、命令词分类、唤醒手势、中文输入原型 | P0 核心链路在目标硬件跑通，形成实测报告 |
| M1：离线产品闭环 | 首页、四模块手动录入、音频本地队列、提醒与异常状态 | 离线、容量、断电测试通过；仅作为原型交付 |
| M2：联网整理 | 配网/授权、转写、核对、幂等与删除 | 云服务条款确定，网络/隐私/数据一致性通过 |
| M3：集成发布 | 正式页面、迁移、专业审核模板、功耗与实机回归 | P0 验收通过，所有未通过项明示并阻止正式发布 |

工程拆分需保持当前架构：App 管理页面流程，领域服务处理规则，存储处理落盘，网络/音频作为独立服务；不得在页面绘制函数中上传、录音或写文件。耗时任务通过事件通知页面，继续保持单一显示所有者。

旧固件迁移须先盘点实际 NVS 占用和记录版本，将校验通过的用户记录复制到用户确认的内存卡并回读核验，随后切换卡为唯一写入源。旧 NVS 在确认迁移前保持只读，核验后提示用户清除迁移副本；不得继续双写。迁移中断可重入，不能重复导入；业务数据改用卡不要求为音频新增 Flash 分区。胎动作为核心应用由 V1 完成 SD 迁移并继续保留普通入口；V2 不重新隐藏入口或将有效记录降为仅 legacy 查阅。
