## 3. 设计原则

1. **同一个键，同一个意思。** 唯一的例外是“计数页”：那里顶键就是页面的主操作，并且页面上写明。
2. **键永远不丢数据。** 不能被键退出的页面（计数中、带未保存输入的编辑/确认页）就忽略侧键，
   顶键在那里也不会静默丢弃记录。
3. **键不制造二次刷新。** 跳转只做一次全刷（≈2 s，见 `CLAUDE.md` 刷新耗时）；
   快捷键的“落点页”必须在应用恢复时就画好，不能先画旧页再改画新页。
4. **失败要看得见。** SD 卡未就绪、时钟读不出、记录已满时，落点页就是应用自己的状态页/提示，不假装成功。
5. **黑白、无动画、绘制与命中同一 `Rect`**，沿用 `DESIGN.md`。

## 4. 按键总表

### 4.1 页面按键策略（每页必须声明一种）

| 策略 | 含义 | 页面 |
| --- | --- | --- |
| **Home** | 同 Free，且这是首页：顶键单击打开功能列表 | 孕周首页（Dashboard）；孕周应用的存储状态页（SD 未就绪时顶键仍能打开列表） |
| **Free** | 侧键 = 切应用；顶键单击 = 回孕周首页 | 孕周宝宝/妈妈；体重仪表盘；胎动今日、趋势、结果、对比、选方式、感觉；设置主页、孕期摘要、存储摘要、更多选项、旧数据迁移 |
| **Pager** | 侧键 = 上/下一页记录；顶键同 Free | 体重历史（P1 先按 Free 处理，见 §11） |
| **Capture** | 顶键按下 = 本页主操作；侧键、顶键单击/双击忽略 | 胎动计数页（1 小时 / 数到 10）（P2 起为 Capture） |
| **Locked** | 侧键忽略；顶键单击/双击仍可离开（页面状态由应用暂停保留，见 §4.5） | 体重编辑/档案/替换确认/删除确认；设置时间编辑、各存储确认页；除孕周外各应用的“读取/保存中”状态页 |
| **Wizard** | 所有键忽略 | 孕周设置向导页（时钟/来源/日期，首次使用无首页可回） |

策略由各应用的纯函数给出（`xxx_page_key_policy(page)`，类型在 `src/ui/key_policy.h`），
应用每次渲染时通过 `sticky_app_set_key_policy(app, policy)` 发布给协调器；协调器按应用分别记录，
应用尚未发布时按 Locked 处理。宿主测试覆盖“每个页面都有明确策略”。

### 4.2 顶键单击

| 当前位置 | 结果 |
| --- | --- |
| 功能列表已打开 | 关闭列表，回到打开前的应用页 |
| 孕周首页（Dashboard） | 打开功能列表 |
| 孕周宝宝页 / 妈妈页 | 孕周首页 |
| 其他应用的任意 Free / Pager / Locked 页 | 孕周首页（切应用，整页全刷） |
| 胎动计数页（Capture） | 记一次（见 §7） |
| 孕周设置向导页 | 忽略 |

循环示例：体重 →（单击）孕周首页 →（单击）功能列表 →（单击）孕周首页。
从体重用底边上滑打开列表时：（单击）关闭回体重，再（单击）孕周首页。

注意“孕周首页”必须是 Dashboard，而不是孕周应用上次停留的页面，
所以需要入口意图 `Home`（§6.1）；现有双击 `select_app(Pregnancy)` 没有这一步。

### 4.3 侧键单按

- **方向**：左键 = 上一个，右键 = 下一个，沿启动器顺序 01 孕周 → 02 体重 → 03 胎动 → 04 设置，首尾循环，与横滑一致。
- **反馈**：复用 `switch_to_neighbor_app()` 的底部黑条局刷，然后一次全刷换页。
- **随屏幕方向**：屏幕转 180° 后“屏幕左侧的键”不再是同一个物理键。方向映射写成纯函数
  `side_key_direction(key, rotation)` 并有宿主测试。**【待确认】** 两个侧键在整机上的实际位置，以及竖屏（90°/270°）时“上一个/下一个”应如何对应——需要拿真机看。
- **连按合并**：400 ms 内的连续同向侧键按一次净步数合并，只换一次页（例如连按两次右 = 跳过一个应用）；
  换页刷新期间收到的侧键丢弃，不排队，避免换完页后又连跳。时间窗 **【待真机调参】**。
- **Pager 页**：翻到首/末页后再按不动作、不刷新。
- **Locked / Capture / 启动器已打开**：忽略（不刷新、不响）。启动器里请用触摸。
- **与休眠组合键的冲突**：单按只在**松开时**判定，且必须同时满足：按住 < 1 s；
  按下到松开期间另一侧键没有被按下；没有刚触发过休眠组合。因此“两侧同按 2 s 休眠”
  不会先误触发一次切应用。长按单个侧键（≥ 1 s）**不做任何事**，保留给以后。

### 4.4 顶键双击（快捷键）

- 在 Free / Pager / Locked（非向导）页：执行“设置 → 快捷键”所选目标；已在目标页时不重复刷新。
- 在 Capture 页：忽略。两次快按在计数页本来就是两次记录意图，且 400 ms 防抖内算一次。
- 启动器已打开：先关闭再执行目标。
- 目标为“关闭”：双击不动作。
- 目标需要的存储未就绪：照常进入目标应用，由它的状态页说明。

### 4.5 事件处理细则（必须实现并测试）

1. **Capture 页的“拖尾点击”**：计数页顶键按下时就计数，随后 iot_button 还会补发 `SingleClick`/`DoubleClick`。
   协调器必须记住“这次按下发生在 Capture 页”，吞掉由它产生的点击事件。
   否则数到 10 的保存页会在 ≈200 ms 后被拖尾的单击带回首页。
2. **唤醒按键不是功能键。** 深睡只能由顶键唤醒，开机后前 ~1 s（**【待真机调参】**）内的顶键事件一律丢弃，
   否则“唤醒的那一下”会被当成回首页或计数。
3. **按键时间戳。** 事件携带按下时刻（`esp_timer`），应用按事件时刻做防抖和计时。
   现状按处理时刻算：计数页一次局刷约 0.9 s，期间排队的几次按键会在同一瞬间被处理，
   400 ms 防抖会把它们全吞掉，丢真实记录。排队的按键处理完后只渲染一次。
4. **应用暂停保留状态。** 顶键从编辑页离开时，应用被暂停而不重置页面（胎动已核对
   `kick_app.cpp:332-340`，体重/设置**【实现时核对】**）。设备随后休眠重启则状态丢失，这与现在“用启动器离开”一致。
5. 计数页只有在 Counter 页、存储就绪、不在状态页时才接受顶键计数。

- **默认 = 体重·记录今日体重**（负责人已确认，2026-10-16）。顶键单击已承担“回首页”，
  双击不必再重复它；体重是每日一次的固定动作，最适合一键直达。
  该默认只是打开今天的输入页，不保存任何数据，保存仍需用户点“保存”。

- 目标做成可追加的表：`ShortcutTarget{ WeightRecordToday=0, BabyWeek=1, KickStart=2, Off=3 }`，
  **0 为默认值**，使零初始化的 `StickyDeviceSettings` 天然等于默认；持久化值只追加不重排（同 `KickMode`）。
  页面上的显示顺序与枚举值无关，按“默认在前”排列。后续新增目标不改页面结构，只加一行。
- 设置主页第 6 行的版面：横屏行高 62 → 56（98 + 6×56 = 434，底部余量 46 ≥ 24 px 安全区）；
  竖屏 6×106 恰好放下（底部余量 52）。按 `CLAUDE.md`“一次只改一个页面”，主页与快捷键页分开做、各自预览。
- 保存失败沿用 `sticky_app_preferences_save_failed()` 的现有提示，不新增一套。

### 5.2 与既有机制的关系

设置应用不直接写偏好。它向协调器发请求（同 `sticky_app_request_language_toggle()`），
由 `DevicePreferencesSync` 异步落盘、失败重试，并在“删除卡内数据”时随之恢复默认。

## 6. 快捷键如何落点

### 6.1 入口意图（Entry Intent）

协调器新增一次性入口意图 `StickyEntry{ None, Home, WeightRecordToday, KickStart }`：

1. 协调器在 `switch_from_paused_to(target)` **之前**把意图交给目标应用。
2. 应用在恢复后的**第一次渲染前**消费意图并决定落点页，所以只有一次全刷。
3. 意图只消费一次；目标应用未就绪（SD 未挂载、仓库未加载）则落到它自己的状态页并丢弃意图，不做“稍后自动重试”。

这与现有 `settings_app_take_pregnancy_request()` 的轮询式做法同源，但统一成一个入口，
避免每增加一个快捷目标就新增一套 `take_*`。

### 6.2 各目标的落点与保护

| 目标 | 落点 | 已在应用内时 |
| --- | --- | --- |
| 孕周首页 | 孕周 Dashboard | 已在 Dashboard：不刷新；在宝宝/妈妈页：回 Dashboard；设置向导页：不动 |
| 体重·记录今日体重 | 体重编辑页，日期 = 今天。今天已有记录则载入该记录（沿用 `AddToday`，保存时走既有“替换确认”）；初值沿用现有逻辑（今天记录 → 最近一条 → 档案基线 → 60.0 kg）。返回 → 仪表盘 | **有未保存输入的页面（编辑/档案/替换确认/删除确认）不重置**，只回到该页；其他体重页打开今日编辑 |
| 胎动·开始计数 | 按记住的方式（§8）：1 小时/数到 10 → 计数页（计时从落点页出现时开始，第一次顶键即第 1 次）；感觉打卡 → 感觉页；未记忆 → 选择方式页。记录已满 → 今日页并提示上限；时钟读不出 → 今日页并提示 | **已有进行中的会话：直接回到计数页，绝不新开**（新开会 `cancel()` 掉已记的数）；其他胎动页：按上面规则开始 |

“进行中”的判据：`s_flow.page()==Counter`，即计数页本身（现有 `counter_` 在应用暂停后保留，计时继续）。

### 6.3 反馈

键没有触点可画按下态。侧键沿用底部黑条（与横滑一致，约 +0.9 s）；顶键/双击先不加，
**【待真机】** 看全刷起始的黑闪是否足够让人确认“按到了”，不够再统一加黑条。

## 7. 胎动页顶键记录

- 计数页（Capture）：顶键**按下**即计数，不等点击判定（避免 iot_button 双击窗口的延迟和把快按误判为双击）。
  效果与点计数圆完全相同：同一个 `KickAction::Count` → `KickFlow::handle_action`，
  所以防抖、数到 10 自动保存、60 分钟封顶都不用另写。
- 渲染：页内局刷；连续局刷满 8 次由显示层自动升全刷（沿用，页面层不另计数）。
- 页面提示：计数圆内文案 `TAP TO RECORD` → `TAP OR TOP KEY`（中文：`点屏幕或按顶部键`；横屏圆内放不下更长的英文），
  页头副标题同步；让用户知道这个键此刻的意思。
- 退出：只能触屏——取消（不保存，放弃）、完成并保存。顶键不能离开，侧键、双击忽略。
  **这是刻意的**：口袋里或半睡中的误触不能把一次进行中的记录送走。
- 提示音：按键后屏幕要 ~0.9 s 才变，想盲操作需要一声很短的蜂鸣确认。
  设备有蜂鸣器，但 V1 当前无按键提示音路径。**【待确认】** 是否要做、默认开关、夜间是否静音；本期不含。

## 8. 胎动记录方式记忆

### 8.1 行为

| 场景 | 行为 |
| --- | --- |
| 首次（未记忆） | “开始计数”→ 选择方式页（现状）。点选后记住并开始 |
| 已记忆 | “开始计数”→ **跳过选择页**：1 小时 / 数到 10 → 计数页；感觉打卡 → 感觉页 |
| 更换 | 今日页方式行点“更换”→ 选择方式页（当前方式反色）→ 点选即记住并开始；该页返回 → 今日页，不改变记忆 |
| 记住的时机 | **点选的那一下**（不是保存成功时）。选了又取消，下次仍是这个方式 |
| 入口一致 | 今日、趋势、对比三页上的“开始”，以及双击快捷键，都走同一条判定，不各写一份 |
| 重置 | 删除卡内数据 / 重置设备偏好 → 恢复“未记忆” |

“感觉打卡”也被记住，保持三种方式对用户一致；此时“开始计数”按钮会打开感觉页而非计数页，
按钮文案随方式变化以免意外（见下）。

### 8.2 今日页

在两个按钮上方加一行方式（≥ 48 px 高，≥ 18 px 字）：

```
记录方式   1 小时计数              [ 更换 ]
[ 开始计数 ]          [ 查看 7 日趋势 ]
```

- 已记忆时主按钮写具体方式：`开始计数`（1 小时、数到 10）/ `感觉打卡`（打卡）。
- 未记忆时该行显示“未选择”，主按钮仍是“开始计数”，点后进选择页。
- 竖屏主按钮在 y=720，一行 56 px 需要挤出约 72 px：**以 `ui_preview` 为准确认今日摘要是否需要压缩**，
  不够就把“更换”并入摘要卡右下角，仍保证 ≥ 48 px 命中区。

### 8.3 为什么不是“从上一条记录推断”

用最近一条 `KickSession.mode` 推断不用改存储，但“选了又取消”会被忘记，
而且双击快捷键本来就需要在偏好里加字段（§9），顺带存方式没有额外迁移成本。
若存储改动得不到批准，可退回推断方案，其余设计不变。

## 9. 数据与存储

在设备偏好里追加两个字段（均 1 字节、只追加枚举值）：

| 字段 | 取值 | 默认 |
| --- | --- | --- |
| `shortcut_target` | 0 体重·记录今日体重 / 1 孕周首页 / 2 胎动·开始计数 / 3 关闭 | 0（体重·记录今日体重） |
| `kick_mode_pref` | 0 未记忆 / 1 1 小时 / 2 数到 10 / 3 感觉打卡 | 0 |

注意 `kick_mode_pref` 不能直接存 `KickMode`：`KickMode::Timed` 的值就是 0，会与“未记忆”冲突，需要 +1 偏移。

- 编解码：现解码要求长度恰好 2 字节（`remaining() != 0` 即判损坏）。需改为“2 字节 = 旧版，新字段取默认；
  4 字节 = 新版”，非法枚举 → `Corrupt`。旧偏好升级后不丢语言和 `last_app`。
- **降级风险**：旧固件读到 4 字节记录会判损坏并回到默认（语言变回英文）。仅影响回刷旧固件的开发场景，需知悉。
- `DevicePreferencesSync` 的“是否脏”比较目前只比 `language`/`last_app`，必须把新字段加进去，否则改了不落盘。
- 应用读写经协调器的原子接口（同 `sticky_app_request_*` 风格），应用之间不互相调用。
- 记忆与快捷键都跟数据集绑定（沿用 `DevicePreferencesSync` 的数据集/挂载代际检查），换卡不串。
